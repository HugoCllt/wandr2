# TBD ledger

Deferrals captured per `CLAUDE.md` §3.1. Nothing speculative ships in code; everything parked here gets picked up when its consumer exists. One bullet each.

## Assumptions

- **Single city / single user POC.** `User.cityId` and `Activity.cityId` are required; the feed is scoped to the connected user's city. Multi-city is out of scope. — spec `2026-05-23-activities-db-ingestion-design.md` §1.
- **Montréal bbox is approximate** (`lat 45.40–45.71`, `lng -73.98 to -73.47`). Tighten with real bounds before relying on it to reject Tavily results. — `prisma/seed.ts`, `City` model.
- **`dedupeKey` uses UTC day + 3-decimal coord rounding (~100 m).** Fuzzy/spelling-variant matching deferred. — `computeDedupeKey.ts`, spec §5/§9.
- **Event expiry compares in UTC.** `City.timezone` is stored but unused until tz-aware "is it past?" logic is needed. — spec §4.1.
- **No authorization on the ingestion MCP server.** stdio = OS-process isolation, no network surface to protect (spec plan-2 Q4). Revisit (bearer token) only if the server is ever exposed over HTTP/remote. — `src/mcp/server.ts`.
- **Dedicated Prisma client in `src/mcp/db.ts`.** The MCP process does not reuse the shared `src/shared/db/prisma.ts` singleton because its string-form `log` writes to stdout (corrupts JSON-RPC). Reconcile the two clients if/when the `apps/web` + `apps/mcp` split happens. — `src/mcp/db.ts`, spec plan-2 §3.
- **Feed ranking is a weighted average of affinity over the category set** (primary ×1, each secondary ×0.5, normalized by `1 + 0.5·|secondary|`). Anonymous users (empty affinity) score `DEFAULT_MATCH_SCORE` regardless of set size. — `src/modules/feed/application/ranking/p1.ts`, spec `2026-05-25-multi-category-activities-design.md` §2.
- **Cross-scout `DUPLICATE` keeps the first ingester's category set** (no merge); `computeDedupeKey` ignores category, so a duplicate only refreshes freshness. Cross-scout consistency is steered by the scout prompt's classification rule, not by code. — `PromoteCandidateUseCase.ts`, `.claude/agents/wandr-theme-scout.md`, spec §6 decision #6.
- **`cursor-codec` `matchScore` is a bounded float** (`z.number().min(0).max(10)`, was `.int()`) to carry the weighted score; the same computed float is the sort key and the cursor key. — `src/modules/feed/application/cursor-codec.ts`, spec §2.
- **Seed upserts on `cityId_dedupeKey`** (since `externalId` was dropped); `dedupeKey` is computed in the loop. — `prisma/seed.ts`, spec §5.
- **Reseed nukes the seed user's data.** `prisma/seed.ts` deletes the seed user (and cascades Account/Session, plus its favorites/calendar/affinities) then recreates it through `auth.api.signUpEmail` so it has a real credential Account. POC only — no prod data. — `prisma/seed.ts`.
- **A signet (bookmark) is one `CalendarEntry` per activity.** `@@unique([userId, activityId])` (was `[userId, activityId, scheduledAt]`); the same activity can't sit on the calendar twice. Events bookmark in one click at their `dateStart`; places open `AddToCalendarDialog` to pick a date. Re-clicking the card signet deletes the entry (`DELETE /api/calendar?activityId=`). — `prisma/schema.prisma` `CalendarEntry`, `src/modules/calendar/web/BookmarkButton.tsx`.
- **Review affinity nudges the primary category only, by fixed deltas.** DONE → +2 (satisfaction ≥ 4) else +1; MISSED → −1, clamped to 0–10. Secondary categories and satisfaction-proportional curves are out of scope for the POC. This is the first writer of `UserCategoryAffinity` outside the seed. — `src/modules/calendar/application/ReviewCalendarEntryUseCase.ts`.
- **Pending-review list is not month-scoped.** The calendar's "À noter" card loads up to 8 past un-reviewed bookmarks across all time (not just the visible month), so a verdict is always reachable regardless of which month the grid shows. — `src/modules/calendar/web/loadPendingReviews.ts`, `src/modules/calendar/application/ListPendingReviewsUseCase.ts`.
- **Schema applies via `prisma db push`, not migrations.** No `prisma/migrations/` dir exists; the Better Auth tables + User profile fields land on the next `pnpm db:push` / `db:migrate` against a live DB. Adopt a migrations baseline if/when a non-disposable DB exists. — `prisma/schema.prisma`.
- **Lenis smooth scroll + the hero-parallax / rail scroll-reveal are scoped to the `(with-sidebar)` group.** `SmoothScroll` is mounted in that layout, so Home / category / favorites / calendar get momentum scrolling and the effects; chat / profile / login keep native scroll. The rail reveal is desktop-only (≥1200px) — the mobile drawer + toggle is unchanged. — `src/app/(with-sidebar)/layout.tsx`, `src/shared/ui/SmoothScroll.tsx`.
- **Chat messages are not persisted — the client owns the visible thread.** `SendChatMessageUseCase` is stateless (only token usage is written to DB); the browser keeps the conversation in React state and replays it each turn. Add a `ChatThread`/message store if cross-device history or server-side moderation is ever needed. — `src/modules/chat/web/ChatPage.tsx`, `src/modules/chat/application/SendChatMessageUseCase.ts`.
- **Chat history is supplied by the client and trusted as-is** (capped at 50 turns, role+text only). The server does not reconcile it against a stored thread. Revisit if abuse (prompt stuffing / spoofed assistant turns) becomes a concern. — `src/modules/chat/web/chatMessagesRoute.ts`.
- **`CHAT_THINKING_EFFORT` only applies to the Ollama provider.** It's passed as `reasoning_effort` in `modelKwargs` on the Ollama branch of `createChatModel`; the OpenRouter branch ignores it (`'none'` is not a standard OpenRouter/OpenAI value and would 400). Add a provider-appropriate thinking control if `CHAT_LLM_PROVIDER=openrouter` ever needs one. — `src/modules/chat/infra/createChatModel.ts`, `src/shared/config/env.ts`.
- **Chat recommendations are ephemeral — never persisted.** The `present`/`synthesize` flow builds a synthetic `ActivityDTO` per card from a web result; it carries placeholder `id`/`slug` and Montréal-centre `latitude`/`longitude` (it's never read from / written to the DB). Persist + dedupe against real activities if reco cards should open a real detail page or be savable. — `src/modules/chat/application/nodes/synthesize.ts`.
- **Chat long-term memory is the DB only — no LangGraph checkpointer/store.** Short-term memory stays client-replayed; long-term is bio/affinities/favorites/calendar via `PrismaRecommendationContextRepository`. No `MemorySaver`/store is wired (out of scope for the single-user POC). Add one if cross-session graph state (resumable threads, interrupts) is ever needed. — `src/modules/chat/application/chatGraph.ts`, `src/modules/chat/infra/PrismaRecommendationContextRepository.ts`.
- **Pipeline token usage sums each LLM call via the graph's `usage` channel.** Router/strategy/synthesize (structured) + converse/present each report `usage_metadata`; the additive reducer sums them and the use case persists the total. Ollama's OpenAI-compatible endpoint sometimes omits usage → that call counts as 0 (same fallback as before). — `src/modules/chat/application/chatState.ts`, `tokenUsage.ts`.
- **`PrismaRecommendationContextRepository` ignores `cityId`.** Favorites/calendar/affinities are already user-scoped and the POC is single-city, so the `cityId` arg is unused (`_cityId`). Scope by city once multi-city exists. — `src/modules/chat/infra/PrismaRecommendationContextRepository.ts`.
- **The `profile` DB read runs even on the clarify path.** `profile` now starts in parallel with `router` (latency win on the recommend path); when the router picks `clarify` the loaded context is simply unused — one cheap wasted query per clarify turn. — `src/modules/chat/application/chatGraph.ts`.
- **Token usage is not persisted when a turn is aborted.** The client's disconnect aborts the graph (`request.signal`), which throws before `usage.addUsage` — tokens consumed up to that point go uncounted toward the monthly cap. Acceptable POC leak. — `src/modules/chat/application/SendChatMessageUseCase.ts`, `src/modules/chat/web/chatMessagesRoute.ts`.
- **Tavily images are aligned to results by index.** Tavily returns page-level `images` separate from `results`; the adapter zips them positionally (`images[i]` → `results[i]`), so a card's photo is approximate, not guaranteed to be of that result's page. Use `include_image_descriptions` / per-result images if precise pairing matters. — `src/modules/chat/infra/TavilyWebSearchProvider.ts`.
- **Login is not mandatory; anonymous visitors browse Home + category pages only.** The `(with-sidebar)` layout no longer calls `requireSession`; the feed loads via `getOptionalUser` (no affinity ranking, no favourites/bookmarks, scoped to the default city). Chat, profile, calendar and favourites stay session-gated (`requireSession` / `getCurrentUser`), so an anonymous favourite/signet click still 401s silently. Widen the public surface only if those pages get an anonymous mode. — `src/app/(with-sidebar)/layout.tsx`, `src/modules/feed/web/feedRoute.ts`, `src/shared/auth/current-user.ts`.
- **Onboarding popup now only appears on a signed-in user's first connection.** `OnboardingGate` is mounted in the layout solely when `getOptionalUser()` resolves a user, and stays blocking (`dismissable={false}`) until the profile form is submitted. Anonymous visitors never see it. — `src/app/(with-sidebar)/layout.tsx`, `src/modules/profile/web/OnboardingGate.tsx`.
- **Chat input toggles fold a French context string into the agent turn, not the bubble.** `Près de moi` / `Ce soir` / `Solo` are client-only toggles; selected hints are joined into a `Contexte : …` sentence appended to the new `HumanMessage` server-side. They do not affect routing/strategy beyond the prompt text. — `src/modules/chat/web/ChatPage.tsx`, `src/modules/chat/application/SendChatMessageUseCase.ts`.
